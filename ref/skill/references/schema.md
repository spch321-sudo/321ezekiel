## 1. 頂層結構

完整的 DATA JSON 有且只有七個鍵:

```json
{
  "ch":      [ {…}, … ],        陣列,每章一個物件,依 n 排序
  "txt":     { "1": [ "…" ], … },  物件,鍵為章號字串
  "blk":     { "1": [ {…} ], … },  物件,鍵為章號字串
  "serm":    { "1": {…}, … },      物件,鍵為章號字串
  "issues":  [ {…}, … ],        全卷共用陣列
  "terrain": { "points": [ … ] },
  "tracks":  [ {…}, … ]
}
```

章號鍵一律用**不補零的字串**:`"1"`、`"12"`、`"22"`。

參考基準(啟示錄 22 章):`blk` 216 個區塊、`serm` 22 篇、`issues` 163 條、`tracks` 4 條、`terrain` 12 點。

## 2. ch — 章層資料

每章物件固定 **16 個欄位**,缺一不可。

| 欄位 | 型別 | 階段 | 說明 |
|---|---|---|---|
| `n` | int | A | 章號 |
| `t` | str | A | 章題。**要有畫面、有動作**,不是主題標籤。「祂的右手,按在我身上」而非「基督的異象」 |
| `sub` | str | A | 副題,三到八字的節奏短語。「聲、光、手」 |
| `lv` | str | A | 難度層級 `"A"`/`"B"`/`"C"`。啟示錄全卷為 A |
| `arc` | str | A | 敘事弧段名。同一段落的連續章節共用,如「七教會」「七號」;插曲章加前綴「插曲:」 |
| `sec` | list | A | 分段大綱,4–7 段。每項 `["1:1--3", "段落標題"]`。節號範圍用**雙連字號** `--` |
| `serm` | obj | A/C | 見第 5 節。階段 A 先寫 `pts`,階段 C 補 `min` 與 `blocks` |
| `q` | str | D | 全章核心問題與答案的開場。先拋一個真實的痛,再給經文的正面回答。100–250 字 |
| `truth` | str | D | 全章中心真理,**一句話**,40–70 字。有轉折、有重量 |
| `mv` | obj | D | 背誦節。`{"t": 和合本經文, "r": "啟1:17--18"}` |
| `card` | list | D | **固定 7 張卡**,見下方分工表 |
| `self` | str | D | 對照 321「看見自己」的一句定義式陳述。如「驕傲的定義:離開人的本位,抓住神的權力,想要代替神。」 |
| `t321` | obj | D | 三軌 321 應用 `{"k":…, "g":…, "p":…}` |
| `grp` | list | D | 小組討論題,5 題(或空陣列) |
| `prac` | obj | D | `{"main": 本週主行動, "items": [4–5 項]}` |
| `safe` | list | D | 講道防呆,7–16 條 |

### card 七張卡的分工

**不是把重點切成七塊**,七張各有職責:

| 索引 | 職責 | 長度 |
|---|---|---|
| `card[0]` | **全章總結** — 整章的內容濃縮成一段完整敘述 | 60–120 字 |
| `card[1]` | **核心真理** — 一句話講明這章的神學重心,常帶原文 | 25–50 字 |
| `card[2]` | **福音要點** — 恩典在這章怎麼運作,常標時態(現在式/完成式) | 30–60 字 |
| `card[3]` | **無己** — 321 的核心應用,必談無己/謙卑/捨己 | 30–60 字 |
| `card[4]` | **主的一句話** — 第一人稱、加引號的短句,像主親口對讀者說 | 10–30 字 |
| `card[5]` | **本週行動** — 具體到可以今天做 | 20–50 字 |
| `card[6]` | **最終整合** — 以 `"最終整合："` 起頭的敘事詩體收尾,短句分行,用 `\n` | 150–400 字 |

`card[6]` 是全章的落幕。短句、換行、留白,像詩。不要寫成散文段落。

### t321 三軌

| 鍵 | 對應 321 | 內容 |
|---|---|---|
| `k` | 耶穌是我的榜樣 | 這章的基督如何成為我的榜樣與同行者 |
| `g` | 讓耶穌作王 | 這章要求我交出什麼、放下什麼權力 |
| `p` | 建立屬神的體系 | 這章如何指向神的國度與體系 |

三軌是三個切面,**不可以講同一件事**。內文可含 `> ` 引言與 `\\` 換行標記。

### prac 五項

`items` 依序覆蓋五個關係層面:**對神、對自己、對人、對生活、對使命**。
每項以層面開頭:`"對神:這一週,每天用五分鐘「轉身」"`。

### safe 防呆的寫法

以「① 錯誤講法」開頭,接一到兩條說明,再接「檢驗標準:…」。三行一組,可有多組。
每一條要指名**一個具體的講錯法**,不是泛泛的提醒。

## 4. blk — 逐節解經

`blk["1"]` 是區塊陣列,每章 6–22 個區塊(平均 10)。每個區塊固定 **8 個欄位**:

| 欄位 | 型別 | 說明 |
|---|---|---|
| `a` | int | 起始節號 |
| `z` | int | 結束節號(單節時 `a === z`) |
| `star` | int | **權重 0–3**,不是開關。0=一般、1=重要、2=關鍵、3=全章樞紐。一章通常有 1–2 個 3,但不是每章都必須有 |
| `grk` | str | **原文**（新約希臘文／舊約希伯來文，一律原文字母）。`<blockquote><p>…</p></blockquote>`，希伯來文加 `dir="rtl" lang="he"`。可留空 |
| `lit` | str | 直譯。同上格式,加「」引號 |
| `key` | str | 字義表 `<table>`。**可以是空字串**——不是每個區塊都需要字義表（實測約三分之一為空） |
| `gram` | str | 語法辨析 HTML |
| `exp` | str | 解經 HTML,300–600 字 |

區塊要照**意義單元**切,不是機械地每三節一塊。

### key 字義表格式

字義表是 **5–7 欄的彈性結構**。前四欄固定,後面視這一段的需要增減:

| 欄 | 必要性 | 內容 |
|---|---|---|
| 中文 | 必要 | 和合本的譯詞 |
| 原文 | 必要 | **原文字母**（見第 9 節） |
| 音譯 | 必要 | 拉丁轉寫 |
| Strong's | 必要 | `G` / `H` + 編號 |
| 構詞／字根／構詞 | 選用 | 字根拆解，用原文字母 |
| 意義／基本字義 | 必要 | 字典義 |
| 本節語境 | 選用 | 這個字在這裡怎麼改變理解 |

最常用的是五欄型（`中文｜原文｜音譯｜Strong's｜意義`），約佔實測語料的八成。
需要拆字根、或需要點出本節特殊用法時，才擴充到六、七欄。

**同一章內盡量用同一種欄型**，讀者掃表時眼睛才不用重新對焦。

```html
<table><tr><th>中文</th><th>原文</th><th>音譯</th><th>Strong’s</th><th>意義</th></tr>
<tr><td>啟示</td><td>Ἀποκάλυψις</td><td>apokalypsis</td><td>G602</td><td>揭去蓋頭</td></tr>
</table>
```

七欄型（需要字根與語境時）：

```html
<table><tr><th>中文</th><th>原文</th><th>音譯</th><th>Strong’s</th><th>字根／構詞</th><th>基本字義</th><th>本節語境</th></tr>
<tr><td>起初</td><td>בְּרֵאשִׁית</td><td>bereshit</td><td>H7225</td><td>√ראשׁ（頭）</td><td>起初</td><td>不是時間的起點，是次序的起點</td></tr>
</table>
```

- 每個區塊列 **4–8 個字**,只列這一段真正吃重的
- 這一段沒有需要拆解的字,`key` 就留空字串,不要硬湊
- 無字根可拆時,`字根／構詞` 填 `—`
- `本節語境` 欄是**這個字在這裡怎麼改變理解**,不是重複基本字義
- 全章解經鑰匙的那個字,`本節語境` 前加 `★`
- 希臘文用 `G` + 編號,希伯來文用 `H` + 編號，且**前綴必須與該列的原文字母一致**
- 「原文」與「字根／構詞」一律原文字母；「音譯」一律拉丁轉寫。詳見第 9 節

### gram 語法辨析

先列各家立場(用 `<ul>` 或編號),再給判斷。判斷用 `<blockquote>` 包起來,以「**最好的理解:**」起頭。

```html
<p><strong>① Ἰησοῦ Χριστοῦ 是什麼所有格？</strong></p>
<ul>
<li><strong>主詞所有格</strong>：「耶穌基督所賜下的啟示」</li>
<li><strong>受詞所有格</strong>：「關於耶穌基督的啟示」</li>
</ul>
<p>上下文支持<strong>主詞所有格為主</strong>。</p>
<blockquote><p><strong>最好的理解：兩者兼具（plenary genitive）</strong></p></blockquote>
```

沒有真爭議的段落,`gram` 可以只講一個值得注意的語法現象,不要硬造爭議。

### exp 解經

`<p>` 段落為主,重點用 `<strong>`,轉折處用 `<blockquote>` 收束。
以一句粗體的破題起頭:`<p><strong>「恩惠、平安」——這是寫給快要被殺的人的問安。</strong></p>`

節奏:**破題 → 處境 → 原文如何解開 → 落到今天的人身上。** 最後一段必須落地,不能停在考據。

## 5. serm — 講章逐字稿

```json
{
  "min": 17,
  "pts": [ ["點題", "1:9--11", "一句話的真理"], … ],
  "blocks": [ ["h", "《章題》"], ["p", "弟兄姊妹平安。"], ["q", "引用經文"], … ]
}
```

| 欄位 | 說明 |
|---|---|
| `min` | 講道分鐘數,**11–32**,典型 15 |
| `pts` | 三個大點(階段 A 就定)。每項 `[點題, 經文範圍, 一句話真理]` |
| `blocks` | 逐字稿,`[類型, 文字]`。類型只有三種 |

`blocks` 類型:

- `"h"` — 標題,**整篇只有一個**,放在第一個 block,格式 `《章題》`
- `"p"` — 講道段落
- `"q"` — 引用(經文、關鍵提問、要停頓強調的句子)

規模基準(取自啟示錄全卷實測):

| 指標 | 範圍 | 典型值 |
|---|---|---|
| block 數 | 210–400 | 280 |
| 總字數 | 3,800–9,500 | 4,900 |
| `p` 段落平均字數 | 15–25 | **18** |
| `q` 佔比 | 2–16% | 8% |

**`min` 與字數必須對得上:講速約每分鐘 300 字。** 4,900 字 ≈ 16 分鐘。兩者兜不攏,通常是其中一個填錯了。

段落要短。平均 18 字——這是講出來的稿,不是寫出來的文。長句在講台上會斷氣。

`q` 用在:引經文、拋核心提問、需要停頓的重話。

結構照 `pts` 的三大點走,開場與收尾各佔約 15%。

## 6. issues — 爭議議題

全卷共用陣列,每卷 4–9 條/章。每條 **9 個欄位**:

```json
{
  "id":   "ISS01_1",
  "t":    "主怎麼快兩千年還沒來？",
  "r":    "1:1",
  "ch":   [1],
  "why":  "一、1:1「必要快成的事」——主怎麼快兩千年還沒來？",
  "pos":  [ ["預備論（Preterist）", "", "這些事在主後70年前後已大致應驗"], … ],
  "con":  [],
  "say":  "本講義的立場：「快」主要指確定性與隨時性。",
  "care": "而彼後3:8–9給了決定性的補充：主不是耽延，是寬容。"
}
```

| 欄位 | 說明 |
|---|---|
| `id` | `ISS` + 兩位章號 + `_` + 章內序號 |
| `t` | 議題標題,用**問句** |
| `r` | 經文出處 |
| `ch` | 涉及章號陣列,可跨章 |
| `why` | 帶中文序號的完整題目描述 |
| `pos` | 各家立場,每項三元組 `[立場名, "", 說明]`(中間欄保留) |
| `con` | **保留欄,一律空陣列** |
| `say` | 本講義的立場,一句話 |
| `care` | 牧養提醒——**這個議題怎麼影響一個人的信心與生活**。技術性澄清類的議題可從缺,但能補就補 |

`pos` 至少兩個立場。真的沒有爭議、只是需要澄清的,`pos` 可只放一項 `["本講義的立場", "", "…"]`。

`care` 是這個結構的靈魂:議題不是為了辯論,是為了保護人。

## 7. terrain — 全卷地勢圖

```json
{ "points": [ [1, 55, 0, "", null], [3, 30, 0, "老底嘉：不冷不熱", "bot"], … ] }
```

每點五元組 `[章號, 高度, 保留位, 標籤, 位置]`:

- **高度 0–100** — 屬靈氣氛的高低。審判、失敗、傾倒偏低;敬拜、得勝、新天新地偏高
- **保留位** — 一律 `0`
- **標籤** — 有標註的點才填,其餘空字串
- **位置** — `"top"`(高峰)、`"bot"`(低谷)、`null`(平地)

不必每章都設點,**取全卷 10–14 個轉折點**即可。這是讓讀者一眼看見全卷起伏的圖,點太密就看不出形狀。

## 8. tracks — 關鍵字追蹤

全卷 3–5 條主線字。每條 7 個欄位:

```json
{
  "gk":   "νικάω",
  "tr":   "nikaō",
  "gl":   "得勝、征服",
  "code": "G3528",
  "root": "νίκη（勝利）",
  "stops": [ ["2:7", "得勝的，我必將生命樹的果子賜給他吃", ""], ["5:5", "…", "top"], … ],
  "ins":  "全卷書用同一個動詞，講了兩套完全相反的紀錄——而終點在17:14。"
}
```

- `gk` 是**原文字母**的單字（新約希臘文／舊約希伯來文），`tr` 是拉丁轉寫，`root` 用原文字母。三者不可互換，見第 9 節
- `code` 前綴須與 `gk` 的字母系統一致：希臘文 `G`、希伯來文 `H`
- `stops` 每站三元組 `[經文, 該處的意義, 位置標記]`,位置標記同 terrain(`"top"`/`"bot"`/`""`)
- 每條 **8–11 站**,依經文順序
- `ins` 是**這個字走完全卷的洞見**——它如何轉折、如何在終點被翻轉。這一句是整條軌道的意義所在

選字標準:**這個字在全卷至少出現八次,而且意義有發展或翻轉。** 只是高頻但沒有發展的字(如「神」),不適合做追蹤。

## 9. 原文的處理:希伯來文與希臘文

### 鐵則:原文欄一律用原文字母

**凡是「原文」的欄位,一律寫原文字母,不寫拉丁轉寫。**

拉丁轉寫只出現在**音譯欄**(`key` 表第三欄、`tracks.tr`),那一欄是給不識原文字母的人念的橋樑,不是原文本身。

| 欄位 | 寫什麼 | 對 | 錯 |
|---|---|---|---|
| `blk.grk` | 原文全段 | `Ἀποκάλυψις Ἰησοῦ Χριστοῦ` | `Apokalypsis Iēsou Christou` |
| `key` 表第二欄「原文」 | 原文單字 | `ἀρνίον` / `חֶסֶד` | `arnion` / `chesed` |
| `key` 表第三欄「音譯」 | 拉丁轉寫 | `arnion` / `chesed` | `ἀρνίον` |
| `key` 表第五欄「字根／構詞」 | 原文字母 | `ἀπό（離）+ καλύπτω（遮蓋）` | `apo + kalyptō` |
| `tracks.gk` | 原文單字 | `νικάω` / `שָׁמַר` | `nikaō` |
| `tracks.tr` | 拉丁轉寫 | `nikaō` / `shamar` | `νικάω` |
| `tracks.root` | 原文字母 | `νίκη（勝利）` / `√קדשׁ` | `nikē` |

原因很簡單:**轉寫會丟資訊。** `ω` 與 `ο` 轉寫都可能寫成 o,`ח` 與 `ה` 轉寫都可能寫成 h。丟了資訊,讀者就無法自己去查、去核對——那正是這套講義最不願意做的事:要人相信作者,而不是給人工具自己看見。

`grk` 欄名沿用歷史命名(HTML 模板依賴它),**語意是「原文」**:新約放希臘文,舊約放希伯來文。不要為了舊約另開新欄位,模板會讀不到。

### 希臘文(新約)

- **必須帶重音與呼氣符號**:`ἀποκάλυψις` 不是 `αποκαλυψις`
- Strong's 編號用 **`G` 前綴**:`G602`
- 字典形(lexical form)寫在 `key` 表第二欄;經文中的實際變化形若與字典形不同,在「本節語境」欄註明
- 兩個字並列用全形斜線:`μαρτυρία／μάρτυς`

### 希伯來文(舊約)

- **必須帶母音點(nikkud)**:`אֱלֹהִים` 不是 `אלהים`。沒有母音點,讀者無從發音,音譯欄也就失去對照的意義
- Strong's 編號用 **`H` 前綴**:`H2617`
- 字根用三子音字根,以希伯來字母寫,前加 `√`:`√קדשׁ`
- 動詞要標**詞幹(binyan)**:Qal、Niphal、Piel、Pual、Hiphil、Hophal、Hithpael。詞幹決定語意方向(主動/被動/使役/反身),這往往就是解經的關鍵
- 名詞標性、數、冠詞;動詞標完成式(Perfect)/未完成式(Imperfect)/敘述式(Wayyiqtol)/祈使/不定詞/分詞

**書寫方向。** 希伯來文是由右至左。在 HTML 欄位裡,整段希伯來經文要包 `dir="rtl"`:

```html
<blockquote dir="rtl" lang="he"><p>בְּרֵאשִׁית בָּרָא אֱלֹהִים אֵת הַשָּׁמַיִם וְאֵת הָאָרֶץ׃</p></blockquote>
```

表格儲存格內的單字不必加 `dir`,瀏覽器會自行處理;但整段引文一定要加,否則標點會跑到錯誤的一端。

**亞蘭文段落**要標明,不要當成希伯來文:但以理 2:4下–7:28、以斯拉 4:8–6:18 與 7:12–26、耶利米書 10:11。在 `key` 表的「本節語境」欄註記「(亞蘭文)」。

### 混用的情況

新約引用舊約時(啟示錄尤其多),`key` 表可同時出現希臘文與希伯來文列。此時**每一列的 Strong's 前綴必須跟該列的原文字母一致**:希臘文列配 `G`,希伯來文列配 `H`。這是校驗器會檢查的項目。

## 10. HTML 標籤慣例

所有 HTML 欄位(`grk`/`lit`/`key`/`gram`/`exp`):

- 只用 `<p> <strong> <em> <ul> <li> <ol> <table> <tr> <th> <td> <blockquote> <br/>`
- 表格可含 `<colgroup> <col> <thead> <tbody>`,且**只有表格結構內**允許 `class=` / `style=`(Pandoc 產出的欄寬會帶)。`dir=` / `lang=` 則任何地方都可用:

```html
<table>
<colgroup><col style="width: 21%"/><col style="width: 79%"/></colgroup>
<thead><tr class="header"><th>層次</th><th>今天的對應</th></tr></thead>
<tbody><tr><td>念</td><td>…</td></tr></tbody>
</table>
```

- **不用** `<div> <span> <h1>–<h6>` — 樣式由模板控制
- **表格以外不用 `class=` / `style=`**。想做小標題就用 `<p><strong>…</strong></p>`,不要用 `<p class="subhead">`
- `<br/>` 自閉合
- 希伯來文引文的 `dir="rtl"` 與 `lang="he"` 是允許的屬性（也是必要的）
- 中文全形括號 `（）`,原文轉寫用半形
- 經文節號範圍在**純文字欄位**用雙連字號 `1:17--18`,在 HTML 內文可用 `–`

其餘純文字欄位(`q`/`truth`/`card`/`t321` 等)**不含 HTML 標籤**,換行用 `\n`。
